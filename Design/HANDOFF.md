# Handoff: ZeusTerm — Constellation Project Scanner & Git Client

## Overview
**ZeusTerm** is a macOS terminal replacement that scans the whole machine and surfaces every
detected software project (macOS/Swift, iOS, web frontend, backend, mobile, scripts, monorepos —
anything Git can detect). It is **terminal‑first**: projects are a visual layer on top of a shell.

The signature idea is a **constellation metaphor**, used at three zoom levels:

1. **Hub** — every detected repo is a *star*, clustered by project type, colored by Git status,
   joined by faint constellation lines to a central monorepo hub.
2. **Worktrees** — clicking a project flies *into* that star; its linked Git worktrees become
   *satellites orbiting* the repo star (one repo, many checkouts).
3. **Branch tree** — clicking a worktree flies into it; its branches & commits form their own
   vertical constellation (newest commit on top → oldest at the bottom).

In the branch‑tree level: **single‑click a commit node** to inspect its changed files + diff in the
bottom panel; **double‑click a commit node** to check out to it (HEAD moves, newer commits dim, a
"detached HEAD" indicator appears).

## About the Design Files
The files in this bundle are **design references created in HTML** — interactive prototypes showing
the intended look, motion, and behavior. They are **not production code to copy directly**. They use
a bespoke streaming "Design Component" runtime (`support.js`, `<x-dc>`, `<sc-for>`) that is specific
to the design tool and should **not** be ported.

The task is to **recreate these designs in the target codebase's environment** using its established
patterns and libraries. Because ZeusTerm is a **macOS desktop app**, the natural target is **SwiftUI
(or AppKit)**; an Electron/Tauri + React build is also viable. If no codebase exists yet, choose the
framework that best fits a native‑feeling macOS terminal app (SwiftUI recommended) and implement there.
Read the logic in `ZeusTerm Live.dc.html` for the exact geometry/state algorithms — translate them,
don't transpile them.

## Fidelity
**High‑fidelity (hifi).** Final colors, typography, spacing, layout, motion, and interaction model
are all specified below and should be reproduced faithfully. The constellation node positions in the
prototype are generated by a seeded algorithm (documented under *Layout algorithms*); you may keep a
similar organic layout or substitute a deterministic layout engine, but preserve the visual character
(clustered stars, glow, connecting lines, orbits, vertical commit graph).

vertically; all node coordinates below are in stage space. The stage is the unit that zoom transforms
are applied to.

- Breadcrumb segments: `ZeusTerm / {project} / {branch}`. Current segment is `#D2D8E6` 600; ancestor segments are `#8A92A4` and clickable (navigate back up, "out" zoom). Separator `/` is `#3F4658`.

  - **Single‑click** a commit node → set `selected` → Changes panel updates to that commit.
  - **Double‑click** a commit node → set `head` (and `selected`) to it → checkout. HEAD ring moves,
    newer commits dim, topbar shows "detached HEAD @{hash}".
  - The header **Checkout** button performs the same checkout for the currently‑selected commit.

## Interactions & Behavior

### Zoom navigation — continuous nested "powers‑of‑ten" zoom (the core motion)
The three levels form **one zoomable space**: a child level lives *inside* the node you clicked and is
anchored at that node's position, so diving in and backing out are exact reverses and the relative scale
between levels is consistent. This is what gives the user a persistent sense of *where they are*.

A single 1040×540 "stage" is transformed in three phases:
- **leave (≈460ms):** the current level pivots on the **focal node** (`transform-origin` = that node's x,y in stage coords) and fades out.
  - Diving **in**: scale `1 → BIG` (BIG = `zoomDepth`, default **7**) — the camera flies *into* the node.
  - Backing **out**: scale `1 → SMALL` (SMALL = `1/BIG × 1.15` ≈ 0.16) — the level collapses *into* the node.
  - Easing `cubic-bezier(.6,0,.78,0)`.
- **enter (instant set, no transition):** the incoming level mounts pre‑scaled, pivoting on the **same focal node**.
  - Diving **in**: starts at `SMALL`, then settles → unfolds *from* the node.
  - Backing **out**: starts at `BIG`, then settles → the node pulls back into place.
- **idle (≈520ms):** settles to `scale(1)` at the same focal origin, opacity 1; easing `cubic-bezier(.16,1,.3,1)` + ease‑out opacity.
- **BIG and SMALL are reciprocals**, so a child is ~1/7 the apparent size at the moment of transition, matching the parent's 7× — the scale step between levels reads as constant.
- **Origin stack:** each dive pushes the focal node's position onto an `origins` array; backing out pops it (or, for a multi‑level breadcrumb hop, reads the origin at the target depth) so the reverse zoom pivots on the correct boundary node.
- Timings: switch to `enter` at 430ms, to `idle` at 480ms. **Pointer events disabled** on the stage while `phase !== 'idle'`.
- **Reduce‑motion:** transitions removed, view switches instantly.

### Back control
A frosted **Back** pill floats at the **top‑left of the star‑map canvas** (`position:absolute; top:16px; left:16px`, `rgba(14,17,23,.72)` + `backdrop-filter:blur(8px)`, 1px hairline border) — shown only below the hub level. It is an overlay on the canvas, **not** in the left rail. The breadcrumb in the topbar performs the same up‑navigation (and supports multi‑level hops).

### Background ambiance
Stars and orbit/commit glows use a CSS `twinkle` keyframe (opacity 0.55↔1, 2.6–5s, staggered delays).
Terminal prompt uses a `blink` step cursor (1.1s). The pulsing rail hint card uses `hintpulse` (2.6s).
These are decorative and stateless.

### Affordances
All interactive nodes use `cursor:pointer` and a hover background tint (`{statusColor}22`). The rail hint
card always names the next action for the current level.

## State Management
Single component state (translate to your platform's idiomatic store — e.g. SwiftUI `@State`/`@Observable`):

| State | Type | Meaning |
|---|---|---|
| `view` | `'hub' \| 'work' \| 'tree'` | Current zoom level |
| `phase` | `'idle' \| 'leave' \| 'enter'` | Transition phase (drives stage transform) |
| `dir` | `'in' \| 'out'` | Zoom direction for the current transition |
| `leaveOrigin` | `{x, y}` | Focal node the *outgoing* level pivots on |
| `enterOrigin` | `{x, y}` | Focal node the *incoming* level pivots on (= leaveOrigin for a reversible zoom) |
| `origins` | `{x,y}[]` | Stack of focal nodes, one per level dived into; popped on back |
| `project` | string \| null | Selected project (set when diving hub→work) |
| `worktree` | object \| null | Selected worktree (set when diving work→tree) |
| `head` | hash string | Currently checked‑out commit (default `12ab9c`, the tip) |
| `selected` | hash string | Commit shown in the Changes panel (default = head) |

**Transitions:**
- hub star click → `dive('work', focal=star, {project})` — pushes `star` onto `origins`.
- worktree click → `dive('tree', focal=wt, {worktree, head:tip, selected:tip})` — pushes `wt`.
- Back pill / single‑step breadcrumb → `backTo(parentView)` — pivots on the popped focal node.
- multi‑level breadcrumb (e.g. tree → ZeusTerm) → `backTo('hub')`, pivoting on the origin at the target depth.
- commit single‑click → `selected = hash`.
- commit double‑click / Checkout button → `head = hash; selected = hash`.
- `detached = head !== tip('12ab9c')`; dim any commit whose time‑rank > head's time‑rank.

**Data:** the prototype hard‑codes sample repos, worktrees, commits, and per‑commit changed files
(seeded so they're stable). In production these come from: filesystem scan for repos, `git worktree list`,
`git log`/libgit2 for the graph, and `git show --stat` / diff for the Changes panel. Checkout maps to
`git checkout <hash>` (or `git switch --detach <hash>`).

## Layout algorithms (reproduce or replace)
- **Hub clusters:** each type cluster has a center (cx,cy) and spread; members are placed on a jittered
  ring around the center — `angle = i/n·2π + jitter + clusterPhase`, `radius = spread·(0.42…1.02)`,
  `y` scaled ×0.82 for a flatter look. A seeded PRNG (mulberry32, seed 1337) keeps it stable.
- **Worktree orbits:** elliptical, `ry = rx·0.72`; nodes evenly spaced per ring with a per‑ring angle offset.
- **Branch tree:** hand‑placed lane columns + time rows (see `cdef`). Newest at top.
You may swap these for a deterministic graph‑layout engine; keep the visual character.
